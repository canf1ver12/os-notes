OS Notes

CHAPTER 01

作業系統概論

Introduction

本章重點

  • 電腦系統由 user、application、operating system、hardware 四層組成，OS 負責把硬體資源抽象化、分配資源、控制程式執行。
  • CPU 知道 I/O 做完的方法有 polling 和 interrupt 兩種；interrupt 靠 interrupt vector 找到對應的 ISR，大量資料則交給 DMA 直接搬。
  • 儲存裝置依速度、價格、揮發性排成階層；電腦架構從單處理器、SMP、multicore、NUMA 到 clustered system。
  • 開機流程：firmware（BIOS / UEFI）→ bootloader（GRUB）→ kernel → init（systemd）→ daemons。
  • dual mode 和 timer 保護系統不被應用程式弄壞；OS 管理 process、memory、storage、cache、I/O 與安全，也可以用虛擬化切出好幾台虛擬機。

核心觀念

電腦系統與 OS 的角色

電腦系統可以分成四層：

  • User：人、機器、其他電腦
  • Application：用資源完成使用者的需求
  • Operating system：控制和協調資源的使用
  • Hardware：提供 CPU 時間、記憶體、I/O 裝置等資源

OS 的角色有三個：

  • Abstraction：把資源包裝成好用的概念，例如把硬碟包裝成「檔案」、把正在跑的程式包裝成「process」
  • Resource manager：決定誰能用 CPU、記憶體分給誰
  • Controller：控制應用程式的執行，包括錯誤處理和安全

目標是 convenient、efficient、robust、secure。

可以把 OS 想成餐廳的外場經理：客人（application）不會自己衝進廚房（hardware）拿鍋子，而是告訴經理要什麼，經理安排廚房、決定誰先上菜、也不讓客人亂動別人的桌子。

Kernel（核心）
OS 裡一直在記憶體中執行、權限最高的核心部分。OS 的主要元件是 kernel、system programs 和 applications，有時還有 middleware（給開發者的資料庫、多媒體、圖形等額外服務）。
Device driver（驅動程式）
每種裝置由一個 device controller 管理，driver 則是 OS 和 controller 之間的翻譯官，把「讀這個檔案」這種通用指令翻成那款裝置聽得懂的指令。

Polling 與 Interrupt

CPU 平常循序執行程式，但也要處理 I/O 裝置的要求。問題是：CPU 怎麼知道裝置什麼時候做完？

  • Polling（輪詢，busy waiting）：CPU 一直去讀裝置的 status register 問「好了沒」，I/O 完成才做下一件事。有 10 個裝置就要分別問 10 次。
  • Interrupt（中斷）：CPU 先去做別的事，裝置好了自己來「敲門」。檢查 interrupt request line 是 CPU 電路內建在指令週期裡的動作，幾乎不花成本。

中斷有兩個來源：

Hardware interrupt
外部裝置透過 interrupt request line 發訊號，非同步，隨時可能來，跟程式跑到哪一行無關。意思是「我做完了，來處理」。
Trap（軟體中斷）
程式自己造成的，同步，一定是執行到那個指令才發生。分成 exception（除以 0、存取不合法記憶體）和 system call（主動請 OS 幫忙，例如讀檔）。
補充

同步或非同步看的不是「是不是故意的」，而是「跟程式執行到哪一行有沒有直接關係」。不管是哪一種，CPU 處理的手續都一樣：

  1. 停下目前的程式
  2. 保存 CPU 狀態和目前的位址
  3. 切到 kernel mode
  4. 用編號查 interrupt vector，跳去對應的 handler
  5. handler 做完，還原狀態，回到原本的程式

Interrupt vector 與 ISR

Interrupt vector（IV）是一個存指標的陣列，放在記憶體最前面，每一格指向一個 ISR（interrupt service routine，真正處理那個中斷的程式碼）。用 interrupt number 當 index 直接查，O(1) 就找到，不用一個一個問「是你嗎？」。

  • 32-bit PC 用記憶體前 1024 bytes 放 IV：每格 4 bytes，共 256 格。不夠用時用 interrupt chaining：每格指向一串 ISR 的 linked list，CPU 沿著 list 一個一個問「是不是你的裝置」，越常用的放越前面。
  • 現代系統有專門的 interrupt controller 幫忙整理、過濾、排序中斷：有優先順序（prioritized），也可以延後（deferrable）。
  • 兩條中斷請求線：non-maskable interrupt（NMI）不能被關掉，用在記憶體錯誤、斷電等重大事件；maskable interrupt可以暫時遮住，例如正在做 critical section 時先別打斷。
  • ISR 在 interrupt context 裡執行，這是 atomic context，執行時不能被打斷。

Top half 與 Bottom half

中斷要很快處理完，才不會打斷原本的工作太久，但很多 ISR 的工作量很大，「做很多事」和「做得很快」是 trade-off。解法是把 ISR 拆成兩段：

  • Top half：中斷一來馬上做，只做最急、最少的事，不能被打斷。
  • Bottom half：等 CPU 方便時再做比較花時間但不急的事，可以被打斷。

網卡的例子：網卡的 buffer 很小，不趕快把封包搬走，下一批就沒地方放、封包會掉。所以 top half 只負責回應硬體、把封包搬進記憶體；解析封包、交給應用程式留給 bottom half。

DMA

大量 I/O 如果每個 byte 都要 CPU 親自搬，會吃掉很多 CPU 時間。DMA（Direct Memory Access）的流程：

  1. CPU 先設好參數：「從 x 位址開始，連續讀 y bytes」。
  2. CPU 就去做別的事了。
  3. device controller 自己把整個 block 從裝置搬進記憶體，不經過 CPU。
  4. 整個 block 搬完才發一次 interrupt 通知 CPU。
no DMA : Device -> Device Controller -> CPU -> Memory
DMA    : Device -> Device Controller --------> Memory   (one interrupt per block)

代價是 DMA 搬資料也要用 bus 存取記憶體，會和 CPU 搶 memory cycles。適合的情境：

  • 鍵盤、滑鼠：資料量少又零散，用 interrupt
  • SSD、硬碟、網卡：資料量大、一次一整塊，用 DMA

Storage hierarchy

儲存裝置依 speed、cost（每 GB 多少錢）、volatility（斷電會不會消失）排成階層：越上面越快、越貴、容量越小。

registers        <- managed by compiler
cache            <- managed by hardware
main memory      <- managed by OS     (primary storage: small, fast, volatile)
NVM / SSD / HDD  <- managed by OS     (secondary storage: nonvolatile)
tertiary storage                     (tape, optical: WORM or RW)

每一層的資料，下一層都有一份（backed by）。問題是改了最上面那份，下面的就過期了：

  • Multitasking：一顆 CPU 輪流跑多個 process，要保證每個 process 讀到的都是最新版本，而不是記憶體裡過期的那份。
  • Multiprocessor：每顆 CPU 有自己的 cache，要靠硬體做 cache coherency。

Computer-system architecture

先分清楚：processor 是一顆實體晶片；CPU（core）是真正執行指令的硬體，一顆 processor 裡可能有好幾個。

SMP（Symmetric Multiprocessing）
好幾顆 processor，每顆有自己的 registers 和 cache，共用同一個 main memory。大家地位一樣，都能跑任何工作，但會搶同一個記憶體。
Multicore
一顆 processor 裡塞好幾個 core，各有 L1 cache、共用 L2 cache。一樣會搶 main memory，但因為有共用的 cache、晶片內溝通快，效能比 SMP 好。
NUMA（Non-Uniform Memory Access）
每顆 CPU 有自己專屬的 memory，CPU 之間用 interconnect 連起來，解決搶記憶體的問題。代價是存取別顆 CPU 的記憶體比較慢，所以 OS 要盡量把程式的資料放在它跑的那顆 CPU 旁邊。
Clustered system
好幾台完整的電腦連在一起合作。high-availability 分 asymmetric（一台工作、一台 hot standby 用 heartbeat 盯著）和 symmetric（全部都在工作、互相盯著）；HPC 則把大計算拆給很多台，程式要寫成能平行化，用 DLM（distributed lock manager）避免同時改同一筆資料，常透過 SAN 共用儲存。優點是 scalability、high availability、low cost。

開機流程

電腦一通電，記憶體是空的，第一條指令從哪裡來？答案是放在 ROM / EEPROM 裡的 boot firmware。

  1. Firmware：BIOS 從固定位置的 boot sector（限 512 bytes）載入第一個 bootloader，難以支援 GUI；UEFI 本身就像一個小 OS，能驅動顯示、網卡、USB，從 FAT-32 格式的 EFI System Partition（ESP）讀 bootloader，一顆硬碟可以放好幾個 OS 的 bootloader。
  2. Second bootloader（例如 GRUB）：在 file system 還沒 mount 之前自己讀檔，找到 kernel image（vmlinuz）和參數，載進記憶體。vmlinuz 開頭有一段沒壓縮的 setup code，負責把後面壓縮的 vmlinux 解開再跳過去執行。
  3. Kernel：重新初始化 CPU registers、device controllers、記憶體管理；先 mount 一個放在 RAM 裡的小檔案系統 initramfs，用裡面的驅動程式讀真正的硬碟後再換成真正的根目錄；填好 interrupt vector。
  4. init（systemd）：把 daemons（背景服務）一個一個叫起來，之後系統就等待 interrupt 並處理。

Multiprogramming 與 Multitasking

Multiprogramming（batch system）是為了效率：一個使用者沒辦法讓 CPU 一直忙，所以記憶體裡放好幾個 job，一個去等 I/O 就換另一個跑。Multitasking（timesharing）是它的延伸：切換得非常頻繁（每幾毫秒換一次），使用者可以同時和每個程式互動，response time 應小於 1 秒。要做到這點需要 CPU scheduling 和 memory management（swapping、virtual memory）。

Dual mode 與 Timer

CPU 本身分不出一道指令來自 OS 還是應用程式，所以用硬體做 dual mode：CPU 裡有一個 mode bit（0 = kernel mode、1 = user mode）。可能危害系統的指令是 privileged instruction，只能在 kernel mode 執行，在 user mode 執行會被硬體擋下。

從 user mode 進到 kernel mode 唯一的路是 trap / interrupt：硬體在跳進 OS 的那一瞬間自動把 mode bit 改成 0，而且跳去執行的是 IV 指到的 OS 程式碼，不是應用程式自己的。kernel mode 也叫 supervisor mode、system mode、privileged mode。

虛擬化需要更多層的 multimode：VMM 跑在最高權限（Ring 0），guest OS 想執行 privileged instruction 會被擋下交給 VMM，VMM 用安全的方式代做（binary translation），讓 guest OS 以為自己成功了。

Timer 防止某個程式無窮迴圈霸佔 CPU：OS 在把 CPU 交出去前，用 privileged instruction 設好 counter，由實體時脈遞減，歸零就發 interrupt，OS 拿回控制權，決定換下一個程式或直接終止超時的程式。

OS 管理的資源

  • Process management：建立、刪除、暫停、恢復 process，提供同步、溝通（IPC）、處理 deadlock 的機制。process 是 program in execution，硬碟上一個 chrome.exe 可以變成好幾個 process。
  • Memory management：記錄記憶體哪些部分被誰使用、決定誰移入移出、分配與釋放。
  • Storage management：把長得不一樣的儲存裝置統一包裝成 file；mass-storage 要做 mounting、free-space management、storage allocation、disk scheduling、partitioning、protection。
  • I/O subsystem：buffering、caching、spooling，加上各裝置的 driver。
  • Protection 與 security：protection 控制誰能存取什麼資源，security 防禦內外部攻擊；用 user ID（UID）和 group ID（GID）設定權限。

虛擬化

Virtual machine 是在一台電腦（host）上假裝出另一台電腦，裡面跑一個完整的 guest OS，由 VMM（hypervisor）管理。

  • Monolithic hypervisor：driver 放在 hypervisor 裡，例如 VMware ESXi。
  • Microkernel hypervisor：由一台有特權的 administrative VM 用自己的 driver 操作硬體，例如 Xen 的 Dom0，其他 DomU 透過 XenBus 把請求送過去。
  • 優點：隔離、搬遷方便、提高硬體使用率與可用性。
  • 顧慮：效能損耗、單點故障。

運算環境除了傳統 PC，還有 mobile（電池、散熱、OS 不能太肥）、client-server、peer-to-peer、cloud computing（IaaS、PaaS、SaaS）等。

實際例子

Python 讀一個檔案，背後發生什麼事？

data = open("grades.csv").read()
  1. 程式不能自己碰硬體，只能用 system call 拜託 OS，觸發 trap，CPU 切到 kernel mode。
  2. OS 找到對應的 device driver，把「讀這個檔案」翻成硬碟控制器聽得懂的指令。
  3. 硬碟很慢，CPU 不會乾等，OS 先把 CPU 切給其他程式（context switch），這個 process 進入 waiting。
  4. controller 用 DMA 把資料一整塊搬進記憶體。
  5. 搬完後發出 interrupt，CPU 暫停手上的事，查 IV 跳到 ISR，OS 把這個 process 改回 ready。
  6. 輪到它時，read() 回傳資料，程式繼續往下跑。

Pseudocode

Polling：CPU 自己一直問

FUNCTION write_char_polling(c)
    device.data = c
    device.command = WRITE
    WHILE device.status != DONE
        // busy waiting：一直讀 status register，什麼事都不能做
    END WHILE
END FUNCTION

CPU 的指令週期如何處理 interrupt

WHILE true
    instruction = fetch(PC)
    decode(instruction)
    execute(instruction)
    // 每道指令做完，硬體檢查 interrupt request line
    IF interrupt_request_line == ON THEN
        n = read_interrupt_number()          // catch：是誰、什麼事
        save(PC, registers)                  // 存好現場
        mode_bit = KERNEL                    // 切到 kernel mode
        PC = interrupt_vector[n]             // dispatch：查表跳到 ISR
    END IF
END WHILE

FUNCTION isr_example()
    save_registers_used_by_isr()
    handle_the_device()                      // top half：只做最急的事
    schedule_bottom_half()                   // 其他留到之後做
    restore_registers()
    return_from_interrupt()                  // 還原 PC 與 mode，回到原程式
END FUNCTION

Timer 保護 CPU

FUNCTION dispatch(process)
    set_timer(time_slice)        // privileged instruction
    switch_to_user_mode_and_run(process)
END FUNCTION

ON timer_interrupt
    IF current.total_time > current.limit THEN
        terminate(current)
    ELSE
        scheduler.pick_next()    // multitasking：換下一個
    END IF
END ON

自我測驗

Q1. 程式執行到除以 0 和使用者按下鍵盤，都會讓 CPU 跳去執行 OS 的程式碼。這兩種中斷分別是同步還是非同步？

答案：除以 0 是同步（trap / exception），按鍵盤是非同步（hardware interrupt）。

原因：判斷標準是「跟程式執行到哪一行有沒有直接關係」。除以 0 一定是執行到那道除法指令才發生，每次執行都在同一個位置；按鍵盤是外部裝置發出的，隨時可能來，跟程式跑到哪無關。

Q2. 為什麼「修改 mode bit」本身必須是 privileged instruction？

答案：否則應用程式可以自己把 mode bit 改成 kernel mode，dual mode 的保護就完全失效。

原因：dual mode 的前提是 user 程式只能透過 trap / interrupt 進入 kernel mode，而且進去後執行的是 IV 指到的 OS 程式碼。如果程式能直接改 mode bit，就能在 kernel mode 執行任意自己的指令，例如改 interrupt vector 或直接操作硬碟。

Q3. 在單核心系統上「暫時關掉 interrupt」可以避免 kernel 資料被同時修改，為什麼在多核心上不夠？

答案：關中斷只影響自己這顆 CPU，其他核心照樣在跑，還是能存取同一塊 shared memory。

原因：單核心時，關掉中斷就不會被 timer 打斷、不會切換到別的程式，所以手上的指令可以一口氣做完。多核心時其他 CPU 根本不需要「打斷你」，它們本來就同時在執行，所以需要第 06 章介紹的 lock 等同步工具。

Q4. 網卡的 ISR 為什麼要拆成 top half 和 bottom half？哪些事情放在 top half？

答案：因為中斷要快速處理完，但完整處理封包很花時間。top half 只回應硬體、把封包從網卡 buffer 搬進記憶體。

原因：網卡 buffer 很小，不趕快搬走，下一批封包進來就沒地方放而被丟掉。封包一旦進了記憶體就安全了，解析、交給應用程式這些費時的工作晚一點做也沒關係，放在可以被打斷的 bottom half，系統就不會因為處理一個中斷卡太久。
